# PowerPico 项目整理和打磨指导方案

文档用途：
本文档是 PowerPico STEP10 之后的代码整理、逻辑简化、项目打磨和面试准备执行依据。
后续每轮只执行本文档中已经列明的一个小步骤，完成验证并记录结果后，再进入下一步。

当前基线：
- 仓库：PowerPico_replica
- 分支：main
- 基线提交：04da229（完成进度到达STEP10，但还未整理代码工程）
- 当前功能状态：STEP9、STEP10 已有用户实机通过记录
- STEP11：暂缓，不纳入本轮整理范围
- BOOT\r\n 开发调试入口：本轮暂不处理
- 本文档创建日期：2026-10-01


============================================================
一、本轮整理目标
============================================================

1. 先删除已经确认没有进入正式工程、没有实际调用的临时代码。
2. 清理历史实验阶段遗留的测试函数、测试变量和测试接口。
3. 保留当前已经验证通过的功能和可靠性逻辑。
4. 保留现有教学式注释，不以减少代码行数为目标。
5. 对仍在运行但难以理解的复杂逻辑补充教学式注释。
6. 在功能行为保持不变的前提下，简化过长、职责混杂的核心函数。
7. 最后再把正式启动逻辑从 test.c 迁移到正式业务文件。
8. 每次只做小范围修改，并分别完成检查、编译、实机回归和Git提交。

最终目标：
- 工程可以正常编译、烧录和运行。
- 当前STEP10功能保持不变。
- 正式代码中不再混有大量已经失效的阶段实验代码。
- 核心数据流能由本人独立讲清楚。
- 面试官从任一核心模块追问时，能够说明“谁写、谁读、为什么这样设计、失败后怎么处理”。


============================================================
二、强制执行边界
============================================================

1. 不做的事情

- 本轮不继续开发STEP11独立BootLoader。
- 不新增A/B分区、回滚系统、事件总线、通用服务框架等新架构。
- 不为了代码短而删除已经验证有效的可靠性逻辑。
- 不整批删除教学式注释。
- 不直接照搬官方源码覆盖当前已经通过实机验证的实现。
- 不同时重构ADC、USB、PD、EEPROM等多个核心模块。
- 不在没有实机问题证据时重写PD协议状态机。
- 不在没有实机问题证据时新增I2C恢复任务或复杂容错状态机。
- 不把官方BootLoader功能写成本人独立实现。

2. 删除代码前必须同时核对

- 全工程源码引用。
- Keil工程文件是否包含该源文件。
- 是否属于HAL弱函数覆盖、IRQ回调、USB回调或LVGL回调。
- 现有map文件中是否存在对应符号。
- 是否通过函数指针、消息队列或回调表间接使用。

只有证据充分时，才能标记为“确认无用”。

3. 修改核心逻辑时必须遵守

- 先画出修改前调用链。
- 记录输入、输出、全局状态和失败路径。
- 一次只修改一个模块。
- 不改变协议格式、任务关系、队列方向和硬件时序含义。
- 修改后先做静态检查，再编译，再进行对应实机回归。
- 如果行为变化无法证明等价，停止修改并恢复到上一提交。


============================================================
三、注释处理规则
============================================================

1. 默认保留的注释

- 教学式注释。
- 指针、缓冲区、队列和状态机的解释。
- 谁写变量、谁读取变量的说明。
- 中断上下文与任务上下文的边界说明。
- 为什么不能阻塞、为什么必须复制数据的说明。
- 为什么切档后需要丢弃数据和进入冷却期的说明。
- USB异步发送缓冲区生命周期说明。
- EEPROM保存失败后恢复旧参数的说明。
- PD会话开始、停止、超时和失败清理说明。
- 经过实机排错后留下的根因说明。

2. 可以随代码一起删除的注释

- 只服务于已删除临时变量的注释。
- 只服务于已删除测试函数的注释。
- “加入Keil Watch窗口观察”等已经不用的调试说明。
- 已经失效的STEP阶段临时说明。
- 注释掉且确认不会恢复的旧代码。
- 与当前真实代码行为不一致的过期说明。

3. 复杂函数建议使用的注释格式

/**
 * @brief 用一句直白的话说明函数职责
 *
 * 谁调用：
 * 输入从哪里来：
 * 修改哪些状态：
 * 输出交给谁：
 * 失败时怎么处理：
 *
 * 执行顺序：
 * 1. ...
 * 2. ...
 * 3. ...
 */

函数内部重点解释“为什么”，不要求把每一条普通赋值重新翻译成中文。

4.2 ADC、DMA和任务处理完整链路
------------------------------------------------------------

主要文件：
- Core/Src/tim.c
- Core/Src/adc.c
- Core/Src/stm32f4xx_it.c
- User/user_AdcDataStrategy.c
- User/Tasks/Src/user_MessageTask.c

必须掌握的主链：
TIM2定时触发ADC
  -> ADC1依次扫描5个通道
  -> DMA循环写入20组五通道数据
  -> DMA半满或全满回调
  -> 中断把10组数据复制到ADC块环形队列
  -> 置位ADC事件标志
  -> MessageSendTask被唤醒
  -> ADC_ProcessPendingBlocks()
  -> Process_ADC_Chunk()
  -> 自动量程、250ms统计、USB波形包

必须能回答：
- ADC五个通道分别是什么。
- 20×5 DMA缓冲区如何分成前后两个半区。
- 前后半区为什么不是高低电平数据。
- 为什么中断中不直接做浮点换算、LCD刷新和USB发送。
- 为什么当前工程增加了ADC块环形队列。
- 环形队列写满后如何处理。
- 为什么数据块必须携带采样时的真实量程。
- ADC错误发生后如何丢弃旧数据并恢复处理。

本轮必须保留：
- DMA半满/全满回调。
- ADC块环形队列。
- 数据块序号和丢块检测。
- ADC错误后的旧数据清理。
- 中断只做必要复制和通知的边界。

4.5 USB接收、协议解析和发送仲裁
------------------------------------------------------------

主要文件：
- USB_DEVICE/App/usbd_cdc_if.c
- User/Tasks/Src/user_MessageTask.c
- User/user_CmdStrategy.c
- User/user_CmdStrategy.h

接收主链：
USB CDC接收回调
  -> 复制本次数据到CmdRxQueue
  -> MessageReceiveTask取出数据
  -> CmdStrategy_ProcessRx()
  -> 寻找帧头、处理半帧和粘包、校验CRC
  -> 执行命令
  -> 回复放入CmdTxQueue

发送主链：
命令回复或最新ADC波形
  -> MessageSendTask统一仲裁
  -> 命令优先
  -> 复制到active_tx
  -> CDC_Transmit_FS()
  -> USB发送完成回调通知任务释放缓冲区

必须能回答：
- 为什么USB一次接收不一定是一整帧。
- 什么是半帧、粘包和帧前噪声。
- 为什么USB接收回调不能只把原缓冲区指针放入队列。
- 为什么接收回调不能阻塞。
- 为什么命令回复优先于连续波形。
- 为什么波形可以保留最新包并覆盖旧包。
- 为什么命令回复不能随便覆盖。
- active_tx为什么在发送完成前不能修改。
- USBD_BUSY和发送失败时当前代码如何处理。

本轮必须保留：
- CmdRxQueue和CmdTxQueue。
- 字节流拆帧。
- CRC16校验。
- 命令与波形的统一USB发送者。
- pending_command、pending_adc、active_tx三类不同状态缓冲区。
- USB发送完成通知。

必须掌握的主链：
UI发送PD_CMD_START

  -> FUSB302检测连接和方向
  -> 接收Source_Capabilities
  -> 选择Fixed PDO或PPS APDO
  -> 生成并发送Request
  -> 接收Accept和PS_RDY
  -> 向UI发送成功或失败事件

必须能回答：
- Fixed PDO和PPS APDO有什么区别。
- CC正插和反插如何识别。
- PB10的CC_EN为什么是PD功能硬件总开关。
- 为什么START前必须清理上一轮协议状态。
- STOP、超时、断线后要清理哪些状态。
- 为什么I2C读取失败不能继续当成有效寄存器值。
- 为什么I2C重试必须设置次数上限。
- 为什么“设置请求参数”和“Request真正发送成功”不是同一件事。
- 当前实机验证过哪些Fixed和PPS结果。

本轮原则：
- PD模块先以理解和补注释为主。
- 没有发现明确重复或无用代码前，不主动重写状态机。
